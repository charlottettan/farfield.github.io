01 / The Claim

The industry is looking at the wrong signal.

Every eval, trust score, and LLM judge measures agents against criteria someone on a technical team decided mattered in advance. Those criteria catch the failures engineers anticipated.

But in production, an agent run finishing is not the end of the job— it is just the moment the draft lands in an analyst's inbox, ERP, or spreadsheet. This is where the real work happens. When the agent gets the tone wrong, hallucinates a detail, or drops a mandatory compliance standard, the employee fixes it by hand.

Because existing tools stop tracking at the API response, this human labor is completely invisible. The organization pays for the agent run, then pays human salary to quietly clean up after it.

02 / Where Farfield Sits

The agent stack ends at output. Farfield begins there.

Model & Inference Layer

Agent Execution Layer
Tool calls, traces, span trees — covered by Raindrop, LangSmith, Arize
Output & Eval Layer
Groundedness, faithfulness, rubric scoring — covered by Judgment Labs, Collibra
Human Interaction Layer Farfield
What employees change in Word, Excel, and email after the agent run — currently unobserved by every tool above

Everything above the human interaction layer assumes the agent run is the last event worth measuring. Farfield is built on the observation that the most important event often happens after the run — when a real employee decides whether the output was actually usable.

03 / What Farfield Does

From correction to improvement, automatically.

01
Capture

Passively logs employee edits and interventions after every agent run — no tickets, no tagging, no engineering effort.

02
Diagnose

Surfaces recurring patterns across employees and tasks. Individual corrections are logged. Patterns generate candidate explanations with supporting evidence.

03
Prioritize

Ranks failure patterns by employee hours and dollar cost. Engineers get actionable items in the tools they already use, not a file to check manually.

04
Improve

Approved fixes go into a staged rollout. If the correction pattern decreases, the update rolls out fleet-wide. One fix, everywhere.

05 / Who It's For

Built for the people responsible for what agents actually produce.

An operations analyst working alongside an agent will not know whether to modify a system prompt, whether a tool is broken, or whether another employee already discovered the same problem. They will fix the result and move on. Farfield makes those corrections useful without requiring every employee to become an agent engineer.

06 / Why Now

The people supervising agents are changing faster than the tooling.

The first wave of AI deployment landed with engineering teams who understood system prompts, had repo access, and could hotfix their own tools. That population is a shrinking share of total agent users.

Agents are now running inside operations, procurement, compliance, and finance. The people supervising them are domain experts who will never open an agent config file. When something goes wrong, they fix the output and move on. Every correction disappears. Every lesson evaporates.

The further agents spread from technical teams, the larger the gap between what agents produce and what employees actually need — and the more of that gap gets absorbed silently as invisible human labor. Farfield is the instrumentation layer for that gap.

07 / Founder Note

While working at Goldman Sachs, we were expected and encouraged to use internal AI tooling daily. The intent was clear, but the floor reality was frustrating: agents made the same mistakes day in and day out, responses never learned from our corrections, and non-technical analysts had no mechanism to push fixes back into the system. You just swallowed the extra work, retyped the output, and moved on.

Between our time seeing operations across Goldman and quantitative environments like Citadel, the gap became obvious. Enterprise IT builds the infrastructure to deploy models safely, but no one is capturing what happens after the output hits the desk. We built Farfield to ensure the corrections employees make every day turn into the data needed to make enterprise AI actually work.
